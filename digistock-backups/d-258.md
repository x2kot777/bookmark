# @cwmasaki (山本 正喜 / kubell CEO (旧Chatwork)) - X 投稿

Author: 山本 正喜 / kubell CEO (旧Chatwork) (@cwmasaki)

Tweet text:
非エンジニアがClaude Codeを使ってカジュアルにVercelなどを使って社内向けアプリを公開することがなぜ危険か？Vercel自体が危険なサービスというわけではなく、むしろかなり強いセキュリティ対策が標準で提供されています。

問題は、Vercelを使うとWebアプリを非常に簡単にインターネットへ公開できるため、Webセキュリティを十分理解していない人でも、サーバーやAPI、データベースを持つアプリを公開できてしまうこと。

URLを誰も知らないからアクセスできないだろうというのは間違いで、インターネットでは脆弱なアプリや認証情報がアップされてないかを常時スキャンし続けているようなボットが多数存在し、発見されて悪用されるケースが日常的に起きています。

また、APIキーなどの秘密情報をクライアント側のコードに含めてしまえば、それを取得されて悪用される可能性があります。秘密情報自体を正しく隠していても、LLMなどを呼び出すAPIに認証や利用制限がなければ、そのAPIを踏み台にして大量に利用され、多額のAPI利用料が発生することもあります。

また、内部で使っているライブラリやフレームワークのバージョンを常に最新に保っていないと、後から発見された脆弱性をつかれて攻撃されます。インターネットに公開しているサービスは常に最新の脆弱性情報を確認し、危険な脆弱性がないようにアップデートし続けないといけません。(企業が運営するSaaSはもちろんそういった保守を行っています)

このあたりのリスクとメンテナンスの必要性を理解していないと、インターネットにサービスを公開するというのは本当に危険なことなのです。
